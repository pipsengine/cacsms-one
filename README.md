# CACSMS ONE — Unified Intelligence Platform

A React/Vite CACSMS ONE hub with an integrated `/sports/*` Sports AI portal. The landing page and Traders portal are preserved. Sports AI's frontend, FastAPI service, SQLite migrations, tests, collectors and worker are all contained in this repository.

## Run

Requires Node.js 20.19+ or 22.12+.

```bash
npm install
npm run dev
```

Open `http://localhost:5173`. For deployment, run `npm run build` and serve `dist/` using your existing frontend hosting.

## Run the Sports AI backend

The Sports AI portal is reachable from the existing Sports AI card or directly at `/sports/dashboard`. It returns to the hub at `/hub`. In one PowerShell terminal:

```powershell
Set-Location 'C:\Projects Development\cacsms-one\backend'
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m playwright install chromium
$env:SPORTS_SQLITE_PATH = Join-Path $env:LOCALAPPDATA 'CACSMS Sports AI\sports-ai.sqlite3'
$env:SPORTS_LOCAL_PREVIEW='1'
$env:SPORTS_ADMIN_API_KEY = 'set-a-private-local-admin-key'
uvicorn main:app --host 127.0.0.1 --port 8011
```

In a second terminal, start the frontend:

```powershell
Set-Location 'C:\Projects Development\cacsms-one'
npm install
npm run dev
```

Open `http://localhost:5173/sports/dashboard`. Vite proxies `/api/sports-ai/*` to the loopback backend. The backend applies additive migrations to the selected SQLite database and creates a timestamped backup before changing an existing database. Keep `SPORTS_SQLITE_PATH` on the same file for the API and worker.

To run scheduled collection and analysis, use a third terminal with the same environment variables:

```powershell
Set-Location 'C:\Projects Development\cacsms-one\backend'
.\.venv\Scripts\Activate.ps1
$env:SPORTS_SQLITE_PATH = Join-Path $env:LOCALAPPDATA 'CACSMS Sports AI\sports-ai.sqlite3'
python worker.py --loop
```

`SPORTS_LOCAL_PREVIEW=1` is strictly for loopback development, never production. This repository does not contain the CACSMS ONE backend/session service, so production authentication and role enforcement must be wired by the host backend before deployment. `SPORTS_ADMIN_API_KEY` protects provider configuration and model activation in the standalone adapter; it is not a replacement for shared SSO/RBAC.

## Sports AI capabilities and data requirements

- **Provider Registry:** The Source Management Centre contains Provider Registry, Website Explorer, Browser Sessions, Extraction Configuration, Data Quality, Collection Scheduler, Collection History and Source Permissions. Collection jobs, source URLs, timestamps, quality errors and admin actions are persisted in the existing SQLite database using additive `sports_ai_` tables.
- **Football:** OpenLigaDB and OpenFootball JSON have working HTTPS adapters. OpenLigaDB uses league/season snapshots; OpenFootball accepts a reviewed raw `openfootball/football.json` season file. Both deduplicate updates by provider ID and map matching fixtures across providers. Their current terms still need administrator review before activation.
- **football-data.org:** The adapter supports competition fixtures, results and standings. Set `SPORTS_FOOTBALL_DATA_API_KEY`; the provider's [coverage page](https://www.football-data.org/coverage) lists free coverage for selected competitions, while its [pricing page](https://www.football-data.org/pricing) describes current plan/rate limits. No key was configured for this implementation's live test, so access was not verified.
- **Basketball:** BALLDONTLIE supports paginated NBA game/result collection and requires `SPORTS_BALLDONTLIE_API_KEY` from an account; see its [API docs](https://docs.balldontlie.io/). SportsDataverse accepts a selected, publicly reachable HTTPS CSV dataset with `id,date,home,away,home_score,away_score` columns and optional `competition,settled_at`. Review the license and attribution for the specific dataset URL; this is not a preselected or bundled dataset.
- **Odds:** The Odds API adapter is available with server-side `SPORTS_ODDS_API_KEY`. Its [current access page](https://the-odds-api.com/#get-access) lists a 500-credit monthly free starter tier; actual coverage/credit use depends on requested sports and markets. No key was configured or tested. No odds are generated by the model.
- **Browser research:** Playwright/Chromium uses an isolated context with no saved cookies or credentials, visits only administrator-approved exact HTTPS hostnames, pins approved hosts to checked public IPs, blocks cross-host requests and private/local network targets, and records page text, configured CSS-field evidence and screenshots. HTTP challenge responses, CAPTCHA/access-verification indicators and likely paywall pages stop extraction; the service never logs in or attempts to defeat controls. BetExplorer is registered as a reference only and remains disabled until its permission is established. Browser research currently visits URLs supplied by the administrator and extracts selectors configured by an administrator; it does not call an LLM or autonomously search the web.
- **Match Research Centre:** Seven tabs show stored fixture overview, prior head-to-head results, cutoff-safe team form, standings snapshots, collected statistics, odds snapshots and stored AI analysis. Each dataset reports source and observation time; missing data is shown as missing rather than synthesized.
- **Scheduling and recovery:** `backend/worker.py --loop` is the only scheduler. It takes a single SQLite leader lease, so a second worker or a FastAPI process does not run the same pass. Enabled, terms-reviewed sources stay on their provider schedules. Workflow state, job attempts, retries, dead letters and recovery cases are stored. Browser research stays permission-gated and is not started by a generic schedule. BetExplorer remains manual.
- **Features and models:** football uses a venue-specific opponent-adjusted Poisson model, a Dixon-Coles low-score correction, and ridge or gradient-boosting rate models only when the chronological sample is large enough. Basketball uses a separate points, margin and Monte Carlo scoring pipeline. Head-to-head, rest, congestion, pace, expected goals, injuries and first-half scores are used only when those source values exist before the fixture cutoff. Recent results use a configurable form half-life.
- **Historical results:** result imports accept an optional timezone-aware `settled_at` timestamp. When omitted, the current time is recorded; settlement cannot predate kickoff. Supply the source's actual settlement time for leakage-safe historical validation.
- **Training and activation:** `POST /api/sports-ai/training/run` performs chronological walk-forward scoring and held-out temperature calibration, reports Brier score, log loss, reliability bins and sample counts, and keeps models inactive. Activation requires sample thresholds, held-out calibration and the separate admin key. Only calibrated match-outcome markets may qualify; other markets remain marked as awaiting calibration.
- **Value:** expected value uses win, half-win, push, half-loss and loss settlement probabilities. Qualification additionally requires a fresh quote, correctly matched fixture, supported market, active validated model and no unresolved high/critical issue. The default minimum edge is 5%; no selection is guaranteed.
- **Automation:** `worker.py --loop` coordinates collection, the prediction queue, due UTC schedules, accumulator monitoring and a daily model evaluation. Schedules and notification rules are installed disabled. Retraining can be requested, but it does not promote the production model. Promotion uses the existing validation gate plus the admin key. The worker never places wagers.

Provider coverage, API quotas, licensing and terms change; review the linked source terms and a dataset's specific license before enabling it. A live collection into the Sports AI SQLite database saved 306 Bundesliga fixtures from OpenLigaDB, 380 English Premier League fixtures from the OpenFootball 2025/26 dataset, and 1,000 NBA games from the SportsDataverse `nba_schedule_2025.csv` release. football-data.org, BALLDONTLIE and The Odds API stay disabled until their environment keys are set. BetExplorer remains a manual reference. Playwright must be installed and `python -m playwright install chromium` completed before browser research can run.

The browser operator is permission-gated browser research, not an LLM agent or search-engine crawler. The host CACSMS service must still wire production SSO/RBAC and enforce administrator authorization; this repository only supplies its standalone development API key/loopback preview. Pace, expected goals, injuries, lineups and first-half markets are calculated only from stored source values; they are not inferred when the provider did not supply them. Non-outcome markets stay uncalibrated until a market-specific holdout exists, so they cannot qualify. Historical model training remains inactive until enough real records with source-accurate settlement timestamps pass the sample, holdout and calibration thresholds. Accumulator tickets are generated only from qualified Phase 2 opportunities. The older `/legacy-analysis` ticket path remains available and is separate. SportyBet booking codes are manual registrations only; no booking-code API is connected and no wager is placed. Email and Telegram delivery are marked sent only after SMTP or Telegram accepts the message. Without `SPORTS_SMTP_HOST`, `SPORTS_SMTP_FROM`, `SPORTS_ALERT_EMAIL`, `SPORTS_TELEGRAM_BOT_TOKEN` and `SPORTS_TELEGRAM_CHAT_ID`, those channels stay `not_configured`. Dashboard alerts are in-app rows. No bookmaker price is generated when a permitted quote is missing. Model drift is recorded and does not replace the active model.

### Provider and browser validation

The committed tests use mocked provider responses for deterministic normalization, credential handling, pagination, deduplication, persistence, retry recovery and browser permission checks:

```powershell
Set-Location 'C:\Projects Development\cacsms-one\backend'
.\.venv\Scripts\Activate.ps1
python -m unittest discover -s ..\tests -v
```

To repeat the permitted local Playwright navigation test:

```powershell
$env:SPORTS_RUN_BROWSER_TESTS='1'
python -m unittest discover -s ..\tests -p 'test_browser_operator.py' -v
```

The test-only `SPORTS_BROWSER_ALLOW_LOCAL_TESTS` flag is set and removed inside that test; never enable it in a deployed backend. Real provider checks require reviewed terms/configuration and provider keys where documented. Use the `Test Connection` action before collection; a provider is marked operational only after collection persists records.

## Integrate with CACSMS Traders

1. Copy `src/Hub.jsx`, `src/styles.css`, `src/portals.js` and `src/assets/` into your existing React frontend.
2. Import `Hub` and add a route to `/hub` using the **existing** React Router. Do not nest a second `BrowserRouter` inside the existing application.
3. Replace the sample portal routes (`/traders`, `/sports`, `/operator`) with the actual routes in the existing application. Make the existing login redirect to `/hub` only after authentication.
4. Supply `config` to `<Hub config={hubConfig} />` using the logged-in user, authorized portals, notification counts and server-derived system status. `defaultHubConfig` is demonstration data and must not be interpreted as live status.
5. Provide `onOpenPortal`, `onRequestAccess`, `onNotifyMe`, `onLogout` callbacks to connect to your backend workflows. A fallback is provided for navigation and explanatory messages, but no access-request or notification backend is bundled.
6. Enforce authorization on the backend and portal routes; hiding cards in the UI is not access control.
7. Configure `/hub` and other SPA routes to serve `index.html` on refresh.

Example:

```jsx
import Hub from './Hub';
<Route path="/hub" element={<Hub config={hubConfig} onOpenPortal={p => navigate(p.route)} onLogout={logout} />} />
```

## Scope and fidelity

The CACSMS ONE landing page remains the hub; the integrated Sports AI module is separate and does not replace the Traders portal. The design is visually close to the generated concept, but exact pixel-level equivalence is not guaranteed across browsers, fonts and screen sizes. The globe and card art are assets; navigation, text, buttons, dates, cards and responsive behavior are real UI.

Portal statuses, user identity, sessions and health are demo defaults until wired to your existing APIs. The date/time display is live in the Africa/Lagos timezone, not hard-coded.
